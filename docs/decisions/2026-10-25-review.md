# 终态架构两轮审阅处置（2026-10-25）

审阅对象：一个 Mod / 两个 Mod 终态草案 v0。审阅者：对抗审阅、第一性原理审阅（Claude Opus 5.5 high，只读）。下表为主线程复核后的处置；被采纳的点已写入 [architecture.md](../architecture.md)。

| 审阅点 | 处置 | 依据 |
|---|---|---|
| F3 不能区分 A/B，解耦兼容键后 A 无此伤 | 接受，推荐改为一个 Mod | `ReplayLauncher.java:37-38` manifest 已带 adapter 与 save_state 标识 |
| I3 白名单要么泛化要么锁版本 | 接受；一个 Mod 不需要白名单 | architecture.md「不做泛化白名单」 |
| I4 去掉 RunHistoryPlus 使统计倒退 | 部分接受：运行时不依赖，读取端保留旧字段，新字段由 record 补 | TinyCat `RunData` 用到的 RHP 字段 |
| Windows 读写冲突 | 接受并升级为 M0 缺陷 | 本机复现 `AccessDeniedException`，`Recorder.java:114` 只捕获 `AtomicMoveNotSupportedException` |
| run.json 体积 | 接受，加 `summary.json` | 本机 39 局中位 1.06 MB、最大 2.49 MB；Python 解析 126 MB/s，千局约 10 秒 |
| R3 判据必然失败 | 一个 Mod 下该测试取消 | — |
| R2 不该挂在求解器上 | 接受 | mod-pair 需要 pybind/CMake |
| R4 真值引擎合成整局 | 接受删除 | 未找到 `.run` 输出证据 |
| M2 验收无判定力 | 接受，改为差异必须归类 | — |
| MPL 混入不是 A 的缺点 | 接受 | MPL 2.0 按文件生效 |
| 底座三层是表面相似 | 接受，只借纪律 | 底座套件 847–1800 秒 |
| xlsx/图片可删 | 未采纳为结论，列为 D3 | 是 TinyCat 社区分享的主要产物，需问使用者 |

## 实测记录

- 写入锁冲突：Java 21，Windows 11，一个 `FileInputStream` 持有目标文件时 `Files.move(ATOMIC_MOVE, REPLACE_EXISTING)` 抛 `AccessDeniedException`，关闭后成功。State Notes `Recorder.java:114` 只捕获 `AtomicMoveNotSupportedException`。
- 记录体积：本机 39 局 `run.json` 中位 1063918 字节，最大 2493037 字节；Python `json` 解析约 126 MB/s。
