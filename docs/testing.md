# Spire Ledger 待测试清单

Last updated: 2026-10-25（对应 main `c1b42ae` 之后）
Product spec: [product.md](product.md) · Metrics: [metrics.md](metrics.md)

维护者这边已经做过的检查：离线断言（`build.ps1 -Check`），以及隔离实例里的无头原生探针。探针用夹具驱动游戏方法，不是真人在玩。下面列的是还没有真人在游戏里验证过的行为。每项都写了怎么做、预期是什么。结果不符合预期时，在 issue 里贴出局的职业、楼层、截图，以及按 Ctrl+Shift+R 生成的错误报告（位置是 `~/.spire-ledger/bug-reports/`）。

## 环境

- 游戏版本 12-18-2022，ModTheSpire 3.30.3，BaseMod 5.56.0，StSLib 2.12.0。
- 在 ModTheSpire 里只勾选 BaseMod、StSLib 和 Spire Ledger。第 B10、B11 项另说。
- 测试用的 `SpireLedger.jar` 由维护者提供。
- 记录写在 `~/.spire-ledger/runs/<run_id>/`。Windows 上是 `C:\Users\<你>\.spire-ledger\`。

## A. 必测（需要真人玩）

| # | 测什么 | 怎么做 | 预期 |
|---|---|---|---|
| A1 | 安装与加载 | 按上面的环境启动游戏 | 正常进入主菜单，顶栏有尖塔账本图标，设置页有两个开关：“Local Spire Ledger recording”和“Turn checkpoint recording (practice/replay)” |
| A2 | 结局：正常死亡 | 打一局，死在任意战斗 | 历史页这一局显示“死亡”，统计页的死亡数加一 |
| A3 | 结局：菜单放弃 | 局中打开设置，选放弃本局 | 显示“放弃”，不显示“死亡”。统计页默认不计放弃局，打开放弃开关后才计入，并算作败局 |
| A4 | 结局：无钥匙通过第三幕 | 不拿三把钥匙打完第三幕 Boss | 显示“胜利”。胜利口径为“击杀心脏”时不算胜，切到“通过第三幕”后算胜 |
| A5 | 结局：击杀心脏 | 拿三把钥匙打完心脏 | 显示“胜利”，两种胜利口径下都算胜 |
| A6 | 存档位分开统计 | 在两个存档位各打至少一局，然后在主菜单切换存档位 | 统计页只显示当前存档位的局；切换存档位后，局数和数字随之变化，不会合在一起 |
| A7 | 每日、自定义、无尽不计入 | 各打一局每日挑战和自定义模式；能开无尽的话也打一局 | 这些局不进入统计页的任何数字。**自定义模式的识别方式目前没有核实过，这一项最需要测** |
| A8 | 统计页筛选 | 逐个试：职业、进阶、结果（全部、仅胜、仅败）、放弃开关、胜利口径、种子局、最小样本量 | 选“仅胜”或“仅败”时，所有胜率类数字显示为“—”，其余数字照常；切换筛选不卡顿、不报错 |
| A9 | 异常退出 | 局中直接结束游戏进程（任务管理器），再重开游戏 | 历史页还能看到这一局，标为“中断”；继续这一局时，记录接着写 |
| A10 | 存读档分支 | 局中保存退出、再读档，并在同一层做出不同选择（SL） | 历史复盘能看到分支；统计只计最终那条路径，被 SL 掉的选择不计入抓率 |
| A11 | 历史复盘 | 打开一局已结束的记录，逐层翻看 | 每层的选择、候选、HP 和金币与你记得的一致 |
| A12 | 回合快照与重打 | 打开设置页的回合快照开关，进战斗打几回合，回退到之前某回合；再从历史页的附件启动练习 | 回退后战斗状态正确；练习结束回到正式游戏后，正式存档、战绩和解锁都没变，练习局不进统计 |
| A13 | 错误报告 | 任意时刻按 Ctrl+Shift+R | `~/.spire-ledger/bug-reports/` 下新增一个 JSON 文件，里面没有账号、令牌和你电脑上的本地路径 |
| A14 | 其他语言与分辨率 | 用英文界面和至少一种没测过的分辨率（如 2560×1440 或超宽屏）打开历史页和统计页 | 文字不溢出、不重叠，按钮都能点。已测过的是简体中文的 1024×768 和 1920×1080 |

## C. 可选（有兴趣再测）

维护者决定不把这两项作为发布前的验收项（2026-10-25）。有兴趣的测试者欢迎测一下，并把结果贴在 issue 里。

**C1 金币估算误差。** 统计里的“累计获得金币”有两种来源。用本 Mod 录的局，记的是游戏内的精确值；只有原版 `.run` 的旧局，是按 TinyCat 的公式估算的。用新版本打至少 10 局后运行：

```powershell
java -cp "build\gson;build\stats-classes" spireledger.stats.GoldCheck <游戏目录>\runs $env:USERPROFILE\.spire-ledger\runs
```

它会逐局打印精确值、估算值和差值，最后给出平均绝对误差和最大误差。TinyCat 在它作者的数据上报告的是 38 和 160。

**C2 千局性能。** 维护者在 1000 局合成记录上实测过：打开统计约 6 秒，每次决策的主线程停顿 p95 约 10 毫秒（[decisions/2026-10-25-review.md](decisions/2026-10-25-review.md)“M1 性能实测”）。这是新统计内核之前的数字。复测方法如下：

1. 用 `java -cp ... spireledger.SummaryPerf make <你的 ~/.spire-ledger/runs> <空目录> 1000` 生成 1000 局。
2. 把生成目录当作一个隔离游戏实例的 `~/.spire-ledger/runs`。
3. 记录从点开统计页到数字显示出来的时间。

**C3 用自己的数据和 TinyCat 对数。** 方法见 [tools/tinycat-compare/README.md](../tools/tinycat-compare/README.md)。维护者的数据已经对到 0 处未归类差异。不同玩家的数据可能暴露新的差异；如果出现未归类差异，把 `compare.py` 的报告贴上来。
