# 练习实例只加载「录制时」的 mod，不加载玩家「当前」装的 mod

## 现象

练习实例（「练习此回合」）启动时，加载的是**这一局录制时用过的 mod**（从该局 manifest 的 `mods` 列表复制），而不是**玩家此刻在 ModTheSpire 里启用的全部 mod**。

举例：玩家平时装了 Colored Map / Colored Powertips / 皮肤 mod，但某局是在只有 BaseMod + StSLib 的环境下录的，那么这局的练习窗口就看不到那些 mod 的效果——和玩家「期望练习窗口就是自己的游戏」不一致。

## 为什么现在是这样（这是有意为之，不是笔误）

`ReplayLauncher.copyRecordedMods()`（2026-11-03 加入）只复制 manifest 里记录的 mod，理由是**正确性**：

- 快照只有在「加载的 mod 集合相同」时才还原得出来；
- manifest 里的组合已经过 `ReplayEnvironment.accepts()` 白名单校验；
- 任意引入录制时没有的 mod，可能改变运行环境（新的怪物、卡牌、事件、`Settings` 改动），导致快照恢复失败或行为漂移。

所以「复制录制时的 mod」是必须保底的下限，「复制玩家当前全部 mod」是它之上的体验增强。

## 期望

练习窗口尽量贴近玩家当前的游戏：在保证快照能恢复的前提下，把玩家当前启用的、且**已被验证兼容**的 mod 也加载进来。

## 难点与风险

1. **版本一致性**：玩家当前 mod 的版本可能和录制时不同，甚至和本 Mod 的已验证白名单不同。加载未验证版本会让 `TurnAdapter.restore()` 的 `restoreReady()` / `compatible()` 判定失败，练习打不开。
2. **行为漂移**：视觉/便利 mod（Colored Map 等）通常是安全的；但改动战斗逻辑的 mod（新怪、新卡、改 RNG）可能让恢复后的棋盘和快照对不上，甚至崩溃。
3. **白名单维护**：每加一个「可随练习加载」的 mod 都要单独验证一遍（对照 `ReplayEnvironment` 的现有白名单机制）。

## 建议方向

- 保留 `copyRecordedMods()` 作为「必加载」集合（快照能恢复的底线）；
- 新增一个「当前启用的额外 mod」白名单（或复用 `ReplayEnvironment` 的白名单），只把**已验证不会破坏恢复**的 mod 补进去；
- 练习窗口明确区分「录制时的 mod」和「额外加载的 mod」，后者加载失败不阻塞练习（降级为只加载录制时集合）。
