状态：**冻结**。相关代码在 `pr18-replica` 分支，**没有进 [PR #20](https://github.com/cyz-dev/spire-ledger/pull/20)**；PR #20 只含统计与导出。等「练习模式的敌人不显示」修好，再单独提复盘 PR。
建立：2026-11-01。跟踪 issue：[#21](https://github.com/cyz-dev/spire-ledger/issues/21)（起点是 [#8](https://github.com/cyz-dev/spire-ledger/issues/8)「A12 回合快照 / 重打无法进入」）。相关规格：[product.md](../product.md)「回合重打」、[architecture.md](../architecture.md)「回合快照的抓取条件」「S/L 分支、快照去重与存储配额」、[testing.md](../testing.md) W11 / W13 / W14 / P1 / P2 / R1 / R2 / N8。

## 0. 一句话

复盘不是「有一个 bug」，而是四层问题叠在一起，任何一层没通，玩家看到的现象都是「点进去没法用」：

| 层 | 问题 | 玩家看到的现象 |
|---|---|---|
| 抓 | 抓取条件复用了恢复条件，等到玩家出完牌才判 | 下拉里几乎没有回合，或只有第 1 回合 |
| 存 | 每次 S/L 重进换分支、整场重记；单点 155 KB 无上限 | 同一回合出现一长串重复条目；每局数据能到 GB |
| 认 | 同一 `(层, 回合)` 多条并列，没有父子关系 | 不知道该选哪条，也不知道哪条是「重试」 |
| 恢复 | 练习实例进入战斗后敌人不显示 | 「练习此回合」进去是空场地 |

## 1. 问题按发现顺序

### 1.1 复盘完全用不了：19 个回合点只有 3 个能重打

**起点是 [#8](https://github.com/cyz-dev/spire-ledger/issues/8)（2026-10-26）：** 开启回合快照后，进战斗打几回合，回退进不去；从历史页启动练习也进不去。当时连「抓到没抓到」都看不见。

**最早的现象。** 打开「最近一局 → 回合重打」，绝大多数楼层显示「本层的回合快照是在已经出牌或弃牌后才观察到的」，能重打的只有零星几个第 1 回合。

**根因。** `TurnRecorder.observe()` 用 `TurnAdapter.stable()` 判断「能不能抓」，而 `stable()` 是 `!HistoryScreen.active() && restoreReady()`——那 15 项条件是为**恢复**服务的（`phase==WAITING_ON_USER`、`endTurnButton.enabled`、四类特效队列全空等）。抓取需要的条件比恢复少得多。用恢复的条件去等，就一路等到玩家出完牌、动作队列清空的那一刻；而 `lastKey` 一旦落盘（无论 `recorded` 还是 `missing`）就锁死该回合，不再重试。

**证据。** `416004e7` 这局：19 个回合点，16 个写成 `missing / first_action_or_opening_discard_already_observed`，只有第 6 层第 1 回合、第 8 层第 1 回合、第 18 层第 1 回合拿到快照；第 2 回合之后连一条记录都没有——`observe()` 根本没走到 key 判断。

**修法（`1a298e1`）。** 拆成两套条件：

- `restoreReady()` 原样保留，只给 `TurnAdapter.restore()` 用——恢复前必须完全静止；
- 新增 `TurnAdapter.capturable()`：战斗房间、无屏幕、`cardQueue` / `actions` / `preTurnActions` 为空、`currentAction` 为空、`turnHasEnded` 为假、`player.isEndingTurn` 为假。去掉 `phase`、`endTurnButton.enabled` 和特效清空这三项瞬态条件——它们正是把抓取拖到出牌之后的原因。

`observe()` 改用 `capturable()`，并且**不再因为本回合已出牌就放弃**：只要 `compatible()` 就抓一份，`played` 字段记 `cardsPlayedThisTurn.size()`（0 = 干净的回合起点，N = 已出 N 张）。原来的 `damageReceivedThisTurn` / `totalDiscardedThisTurn` 判据删掉——回合开始结算的中毒、荆棘伤害和开局弃牌会把它们置位，但与「玩家是否出牌」无关。

另外补了「为什么没抓到」的上报（`e11dafa`）：`TurnRecorder.blocker` + 历史页 `blockerText()`，不再静默写成一句笼统的「没有快照」。

**状态：** 已修，等 W11 手测。

### 1.2 S/L 之后到底记不记：不记就丢样本，全记就爆盘

**现象。** 每次保存退出、重新读档，同一条战斗会从第 1 回合重新记一遍；第 20 层第 1 回合在 manifest 里有 9 条，5 条有效。

**根因。** `Recorder` 构造函数每次进程启动都新建 `branch`（`forkBranch()` 只给「回合重打」用），而 `lastKey` 只存在内存里。于是每次 S/L 都是新分支 + 从头重记。实测同一局：36 个快照点、**26 个分支**、0 个 `turn_rollback` 事件。单点约 155 KB，`MAX_POINTS=10000` 折合每局约 1.5 GB。

**取舍。** 分支不是噪音：S/L 的每一次尝试都是「同一状态、不同动作、不同结果」的配对样本，训练时必须保留。所以**不采用**「清空重记」或「只记 nosl 到底」，仍走增量写入。要改的是三件事：分支要有父子关系、重复内容不重复落盘、总量有上限。

**修法（`a23f8c1` spec + `cd379ec` 代码）：**

- **分支树**：`Recorder` 新增 `branchParent`、`branchParentSnapshot`、`branchReason`。构造时读 `replay/manifest.json` 最后一条快照当父节点，理由 `process_restart`；`forkBranch()`（回合重打）理由 `in_combat_turn_rollback`。每条快照带 `branch_parent` / `branch_parent_snapshot` / `branch_reason`。
- **S/L 判定**：`Hooks` 给 `SaveAndContinue.loadSaveFile` 打前置补丁，把「刚读档」告诉 `TurnRecorder`；`battle()` 据此分三种情况：SaveState 恢复（沿用 `combat_id`）、读档回同一楼层（沿用 `combat_id`，理由 `native_load`，下一次抓取带 `parent_snapshot`）、其余为新战斗。
- **内容去重**：写入前对快照状态主体算 SHA-256（剔除 `captured_at`、`snapshot_id`，保留 `run_id/branch_id/combat_id/floor/turn`）。manifest 新增 `blobs` 表；内容已存在就复用同一个 `turns/<uuid>.json`，条目记 `availability="duplicate"` + `duplicate_of`。
- **配额**：单局 `BUDGET_BYTES = 512 MB`（约 3000 个不同快照点），可用 `-Dspireledger.turnBudgetMb` 覆盖。超预算按 `captured_at` 从旧到新淘汰**最老的分支**（当前分支与主链最后一条永远保留）：条目改 `availability="evicted"`、清空 `relative_path`，`snapshot_id/floor/turn/played` 保留，随后删掉不再被引用的 blob。淘汰不删记录，训练侧能看出「这里曾有数据、内容已回收」，界面只列 `recorded`。

**状态：** 已修，等 W13 / W14 手测。

### 1.3 历史页一屏全是「第 1 回合」

**现象。** 同一 `(层, 回合)` 并列出现 9 行，玩家不知道该点哪条，看起来像 bug。

**修法（`0f83c6d`）。** 折叠成一个代表（最新那份），标签后缀「另 N 次」；选中后出现「尝试」下拉，可在该回合的多次尝试之间切换并各自重打。旧尝试仍可选、可重打。状态完全相同的重进不新增条目（`duplicate`），所以不会再堆。

**状态：** 已修。**但用户实测反馈「复盘这次成功，截图下拉异常」——这条没有定位**，见第 3 节。

### 1.4 事件选项是英文

**现象。** 统计页事件行显示 `金币 金币 药水` 之类英文原文。

**根因。** 事件名有官方汉化（`EventHelper.getEventName`），但 `.run` 里的 `player_choice` 是事件类构造时传进去的字符串，**游戏没有给它的本地化 key**。

**修法（`ec88d80`）。** 新增 `EventText`：内置 110 条英文→中文（含组合词），本机 111 种选项全部命中；玩家可在 `~/.spire-ledger/i18n/event-choices.tsv` 按「英文 TAB 中文」补充，未命中的在页脚列出。

**状态：** 已修（属于统计页，随 PR #20 一起走）。

### 1.5 白名单：不影响 RNG 的 Mod 该不该放行

**问题。** 装了卡图替换类 Mod 就整局判为「未审核组合」，复盘直接不可用。

**修法（`3cf9582`）。** `ReplayEnvironment` 白名单加入 `CardImageReplacer 2.0`（只改贴图，不改战斗状态、不进快照字段），**2.1 仍拒绝**（未审阅）。版本精确匹配，不设下限。

**状态：** 已修，等 N8 手测。

### 1.6 练习模式的敌人不显示（**未修，冻结原因**）

**现象。** 点「练习此回合」进入独立实例，战斗可以操作，但**敌人不显示**，场地是空的。

**已知。** 与 SaveState 恢复后的 Spine 资源有关：快照恢复的是状态数据，怪物渲染依赖的 `.atlas` / 贴图没有被重新加载或没有跟着子进程一起初始化。

**状态：** 未定位、未修。按用户决定先冻结——这是复盘能不能交付的关键项，修不好整个复盘 PR 都不该发。

## 5. 为什么不删掉重做

- 分支树与去重是**训练数据**的基础设施，删了等于把 S/L 的配对样本扔掉；
- 抓取条件的修法（`capturable()` vs `restoreReady()`）是对的，只是没在游戏里验完；
- 剩下的是一个渲染问题和一个下拉问题，不是架构问题。

所以选择「冻结 + 记录」，而不是回退。
