Architecture: [architecture.md](architecture.md)

## Purpose

Spire Ledger（尖塔账本）是《杀戮尖塔 1》的本地记录、统计与复盘 Mod，由用户维护和发布，GPL 开源。它把每局的事实如实记下来，汇总成玩家自己的统计和 Tierlist，并支持按层复盘和回合重打。它独立、离线，不依赖网络、求解器或训练环境，也能和用户的求解器 Mod 同装使用。

它要回答玩家的三类问题：我当时有哪些选择、选了什么；我在哪些遭遇、遗物和构筑下赢或输；我能否回到某个回合重打。因此三条事实必须可信：记录可追溯到当时的游戏状态，统计不重复计数且口径写明，练习和重打不损害正式存档与战绩。

它接替 State Notes（`sts1/sts1-state-notes`，0.4.0 未公开发布）：State Notes 的记录、复盘与重打能力迁入本项目并改名。TinyCat（MI，MPL-2.0）只作为统计口径与领域知识的参考，不并入代码，也不自动成为验收真值。

## Expectations

### 安装与运行

- 玩家放入一个 `SpireLedger.jar`，在 ModTheSpire 中勾选 BaseMod、StSLib 和 Spire Ledger 即可使用。
- 支持同装 SuperFastMode 1.0.8：照常记录、统计和回合重打，独立练习沿用当前 SuperFastMode 配置。其他版本需单独验证。（用户要求，2026-10-26）
- 支持与求解器 Mod（`sts1solver`）同装：记录和统计照常工作，求解器执行的动作标为 `known_automation`，人的操作仍为 `human`；求解器 0.9.6 及以后的版本同装时支持回合重打，回退先取消旧计算结果并停止自动操作。（用户更新要求，2026-10-26）两个 Mod 互认：求解器发版不必再改账本，只要保留账本调用的取消与停止入口；求解器 0.9.7 起也把账本列为受信任 Mod。（用户要求，2026-10-28）
- 加载其他未审核的 Mod 时照常记录，操作来源记为 `unknown`，回合重打拒绝启用。
- 同时加载原装 SaveStateMod 时拒绝启动并提示移除。
- 另一个 Mod 截获了鼠标点击、账本的下拉或按钮因此点不开时，账本顶部显示一行红色告警：说明点击被其他 Mod 截获，列出已加载的未审核 Mod，并提示按 Ctrl+Shift+R 生成诊断报告。只装已审核 Mod 时不会出现。（用户决定，2026-11-03，issue #26，参照求解器对不兼容 Mod 的告警）
- 记录、错误报告、练习实例、导出和替换图都留在 `~/.spire-ledger/`，不放进游戏目录：卸载或重装游戏会连同游戏目录一起删除，装在 `Program Files` 下时游戏目录不可写，同一台机器上的多份游戏安装也会各存一份。导出完成后有“打开文件夹”。（用户决定，2026-11-03，审阅 PR #22、#23）

### 记录

- 需要完整记录候选的决策类型以 [metrics.md](metrics.md) 的清单为准，至少包括战后选牌、商店和尼奥。每次选择确认前记录完整牌组（逐实例）、资源、遗物和全部候选；跳过、歌唱碗和最终离开分别记录，暂时关闭后重新打开不算一次新选择。商店候选记录展示时的价格和可买状态；尼奥记录全部选项的收益与代价。（商店与尼奥为新增，proposed）
- 原版 `.run` 的尼奥选项从 `neow_bonuses_skipped_log` / `neow_costs_skipped_log` 还原为“所选 + 未选”的完整选择集；账本记录从 `NEOW_OPTION` 的候选还原。没有未选记录的旧局只保留选中项，不参与标准率拟合。（2026-10-29）
- 资源快照包含累计获得金币，起点、计入的获得事件和 SL 后的路径口径写在 [metrics.md](metrics.md)。入层 HP 取进入房间、房间效果生效之前的值，不靠估算。（采样边界为 proposed）
- 构筑变化以前后锚点表示，不猜原因。SL 记为新分支并关联父检查点。
- 记录写在本机 `~/.spire-ledger/runs/<run_id>/`。异常退出后，已落盘的记录仍能从游戏内历史入口查看，不完整的尾部标为“中断”；派生文件损坏不得让整局记录消失。（proposed）
- 记录失败不阻断游戏；停录后持续显示停录状态，并在该局记录里标出缺失区间。（proposed）
- 记录格式升级只增字段、不改既有字段含义，旧记录持续可读；遇到不支持的版本时明确报告，并保留原文件不动。State Notes 0.4.0 的旧记录（`~/.sts1-state-notes/`，schema `sts1-state-v1`）原地只读，照常进入统计与复盘，新 Mod 不迁移、不改写。（用户决定，2026-10-25）

### 统计

**样本范围**

- 覆盖全部进阶，进阶作为筛选项；另可按职业、日期、结果、是否计入放弃、种子局、最小样本量筛选。（用户决定，2026-10-25）
- 每个逻辑对局只计一次：只使用最终有效路径及可确认的祖先片段，其余 SL 分支只用于复盘。练习实例、测试夹具和未完成局不进入正式统计。（proposed，沿用现有实现的分支口径）
- 统计按存档位分开：只统计当前存档位的局，不合并多个存档位，与游戏自带的历史记录一致。每日挑战、自定义模式和无尽模式不进入统计，也不提供单独查看。（用户决定，2026-10-25）
- 求解器参与的局照常进入统计，并标明自动化或人机混合来源。选择类排名排除已知自动化的选择；来源不明的选择计入，并单独显示其数量与占比（理由见 [metrics.md](metrics.md) 3.4）。（proposed）

**胜负口径**

- 每局保留三个独立事实：最终结局（胜、死亡、放弃、未完成）、是否通过第三幕、是否击杀心脏。（proposed，2026-10-25 协作者提出、审阅修订）
- “胜”默认指击杀心脏，可切换为“通过第三幕即算胜”。切换后，通过第三幕、死在第四幕的局也算胜；所选口径需要的事实缺失时，该局计为“未知”，不强判为败。（proposed）
- 结果筛选取值为全部、仅胜、仅败。放弃局默认排除；开启放弃开关后计为败，出现在“全部”和“仅败”中，“仅胜”始终不含放弃局。按胜负筛选时，所有胜率类指标（包括遗物的持有胜率）显示为“—”，其余指标照常计算。（proposed）

**来源合并**

- 数据来自本 Mod 的记录和原版 `.run`。旧 `.run` 里有 RunHistoryPlus 写入的字段时照读，但运行时不依赖 RunHistoryPlus。
- 相同 `play_id` 的多份来源合并为一个统计对象，同一记录的副本不重复计数，不按种子猜测关联。各字段保留来源，并按 [metrics.md](metrics.md) 声明的优先级取值；身份或同等级事实冲突时明确标记冲突，受影响的字段不参与计算。没有关联上的记录保留独立身份，并显示关联状态。结果与读取顺序无关。（proposed）

**指标与显示**

- 每个指标在 [metrics.md](metrics.md) 声明统计单位（局、战斗、选择次数）、适用样本、分子分母或模型含义、缺失与估算规则，以及最小样本量按什么计数。M1 开始补字段前，M2 和 M3 的指标清单先在这里定下。（proposed）
- 总览同时给出平均终局牌组大小、平均得分、商店平均删牌、事件平均删牌和平均每局删牌；每个均值和胜率附 95% 区间（胜率用 Wilson，均值用 ±1.96 标准误），不改变既有指标的分子分母。删牌口径按 TinyCat：商店、事件、火堆抽烟、涅奥移除与空鸟笼。（2026-10-29，用户要求）
- 选择类指标同时提供“一般率”和“标准率”。卡牌、涅奥与 Boss 遗物采用 TinyCat 的 Plackett-Luce 同屏拟合（`standardized-v2`），火堆采用“占比 ÷ 随机基线”的标准化倍（`campfire-v1`）。标准率显示有效样本量、模型口径和无法拟合的“—”；卡牌的两份视图都列出跳过：一般率里是跳过率，标准率里是跳过的份额；歌唱碗也算“这屏不拿牌”，它自己的实际选取率另标“实际占比”，只作参考；不再单设“跳过与歌唱碗”页，两者在卡牌页的两份视图里已经分别给出。卡牌抓率的样本是 `.run` 里**全部** `card_choices` 屏：战后奖励、事件（如感官石）、商店星盘、捕梦网火堆、涅奥开局都算，无色牌因此出现在列表里；变牌不产生选牌记录，本来就不在统计范围内。（2026-11-01 修正旧口径：此前只取有战斗的楼层，无色牌整类缺席）两份口径并列展示，不能相减，也不作为卡牌强度结论。（2026-10-29 用户要求；2026-10-30 起报告跳过的份额，维护者在 PR #18 审阅中决定）
- 涅奥与 Boss 遗物另设独立的“胜率”口径：选了该选项/遗物的局里赢了多少（选后相关，不是该选项带来的收益），每局只计一次，胜负未知的局不当作败局；仅胜/仅败筛选下显示“—”，界面暂不显示区间，CSV 给出 Wilson 区间作提示。三种口径分开显示，不再把胜率混进选取列表。Boss 遗物在三种口径下都按幕分组。（2026-10-30，PR #18 提出，维护者审阅后保留）
- “战斗与资源”下的遭遇平均承伤、遭遇死亡率、药水使用、商店购买与删除、火堆行动、事件选择、实际战损都按幕分组：先列不带幕号的总计，再按“第 N 幕 · …”插入该幕，顶部“幕”下拉可选全部或第 1–4 幕（Boss 遗物只有第 1–2 幕）。商店与事件的分幕值来自原版战绩的购买楼层、删牌楼层和事件楼层，构成记录（Ledger）没有这些楼层，只进总计，页脚写明。（2026-11-01 增加商店与事件，此前只有承伤、死亡、药水、火堆、战损）
- “事件选择”页的两种口径分开显示，不混排：顶部下拉选“次数”只列各事件选项被选中的次数，选“胜率”只列选了该选项的局里赢了多少（选后相关，每局只计一次）。单位不同（事件次数 / 局），所以不并列；仅胜/仅败筛选下所有胜率行显示“—”。事件没有标准化拟合，不给“标准率”档。默认是次数。（2026-11-01，此前两行混在同一张表里，读不出“遇到多少次”和“赢了多少局”的区别）
- 观测比率同时显示分子和分母；模型指标（如标准化抓率）显示有效样本量和模型口径。“已知为零”“未记录”“不适用”分开处理，缺失不当作 0；覆盖率按该指标的统计单位计算；估算值明确标注。
- 遗物统计：`.run` 里有 Relic Stats 写入的 `relic_stats` 时照读，按遗物汇总效果量（如燃烧之血回血、金神像金币）。只展示语义对照表已确认的效果维度和单位；只有上游按战斗计量的遗物才给每场战斗和每回合平均值，分母从获得该遗物时算起，无法确认分母时显示缺失。“持有”指该局结束时仍持有。效果量和持有胜率分别显示有效样本。运行时不依赖 Relic Stats，也不重写它的局内计数；对照表依据 Relic Stats（MIT）源码整理，NOTICE 署名。（proposed，2026-10-25 用户提出）
- 卡牌和尼奥的选择排名（Tierlist、标准化抓率）只描述玩家自己的选择行为，不给推荐理由，也不判断卡牌强弱；怪物排名描述所选样本里的遭遇结果。（proposed）
- 打开或关闭统计界面不改变局内状态，也不推进 RNG。

### 性能与存储

- 性能够用即可，不设硬性上限；不为性能引入难以维护的结构。M1 实测（1000 局打开约 6 秒，每次决策主线程停顿 p95 约 10 毫秒）作为回归基线，明显变差时再处理；维护者不再复测，有兴趣的测试者可按 [testing.md](testing.md) 自测。（用户决定，2026-10-25）
- 回合附件和练习实例的磁盘占用可在游戏内查看，并可由玩家删除；磁盘空间不足时停止新增附件并提示，已有记录保留。（proposed）

### 导出

- 统计导出已完成五类内容：卡牌抓率、火堆行动、涅奥选项、Boss 遗物、实际战损。从个人统计进入“导出”，先选内容；有幕的内容再选幕（卡牌、火堆、实际战损为 1–4 幕，Boss 遗物为 1–2 幕，涅奥没有幕）；幕下拉另有“全部”。卡牌可选一般率/标准率；涅奥和 Boss 遗物可选一般率/标准率/胜率；火堆可选行动次数/标准化倍；实际战损不分口径、直接按幕。界面只有一个“导出 PNG+CSV”按钮：幕选具体幕时写该幕，幕选“全部”时一次写出该内容的每一幕（每幕单独成图，不合并长图）；两种方式都写一个 `metrics.csv`（全部时按幕分成多张表）和 `metadata.json`。涅奥和 Boss 遗物含 `<kind>-win.png`。图片宽度 1600px，超高图分块渲染后拼接为单个 PNG。导出到 `~/.spire-ledger/exports/<时间戳>-<短 UUID>/`。（2026-10-30，2026-10-31 增加选幕与全部导出）
- 图片内容：一般率卡图保留 T0–T6；标准率卡图使用 S、A、B、C、D、R0、R00 强度分档，跳过参与分档并显示份额，歌唱碗并入跳过、另列实际占比；火堆、涅奥和 Boss 遗物按段做 Fisher-Jenks 分档（`section-tiers-v1`，最多 7 档 S–R00，同值同档），行动次数是计数不分档，标准化倍里的睡觉是占比、也不分档；火堆按幕分节并显示 `占比 倍数`；涅奥显示被选/出现（一般率）、强度份额（标准率）或胜率（选了该选项的局里赢了多少）；Boss 遗物按幕分节，跳过在一般率、标准率和胜率里都照常出现；实际战损按幕分节，每幕先列该幕每局总战损，再按场均战损降序列出各遭遇，数值是生命；第 1–3 幕参考 TinyCat 把 Boss 单列 T0、其余按场均战损等人数分 T1–T4，第四幕与事件战不分档。“跳过”用空白卡图占位，涅奥使用空白卡图占位，Boss 使用游戏内遗物图片，实际战损的遭遇图见下一条。
- 实际战损的预览和导出图里，每个遭遇显示玩家本机游戏为它生成的怪物形象（多只怪的遭遇画在一起），画法与战斗中的待机姿态一致；绘制不推进任何对局随机数。`~/.spire-ledger/monster-images/` 或 `mods/SpireLedger/monster-images/` 里与遭遇同名的 png/jpg 优先，用来换图；不读其他 Mod 的目录。游戏不认识的遭遇（例如未加载的 Mod 遭遇）显示空白卡框。发布包不带任何图片，也不联网下载。（用户决定，2026-11-01）
- `metadata.json` 写入 `metrics_version`、`tier_version`、`section_tier_version`（实际战损不写）、`standardized_version`、`csv_version`、内容类型、当前幕、`all_acts`/`acts`（本次实际写出的幕）、局数、`views`（`observed`/`standardized`/`win`）、抬头文字（含分档算法）、筛选、排除原因、CSV 范围说明、`remarks` 和该内容的 entries/sections。图片抬头固定 4 行：职业、进阶、结果、胜负口径、放弃开关；选中局数、胜率与分子分母、最少出现次数；本图口径；分档说明。日期、存档位、模式、种子局、来源与 SL 路径、操作来源未知计数、排除的自动化局数、口径版本和导出时间只写 `metadata.json` 的 `remarks`，不印在图上。选中的账本局含已知自动化操作时标题加“含求解器”；原版 `.run` 不参与判定。（用户决定，2026-11-01，接手 PR #20：抬头 4 行，机器字段进 `remarks`）
- 导出内容与当前界面的统计结果一致，并附带筛选条件、胜负口径、来源范围、有效样本量、缺失与估算标记，以及口径版本。这些元数据写进同目录的 `metadata.json`；图上只印抬头 4 行（筛选两句、本图口径、分档说明），保证图本身读得懂，明细去 `metadata.json` 查。`metrics.csv` 为 UTF-8 带 BOM、RFC 4180、中文列名（`csv-v2`），只写本次导出的幕与条目，按幕/口径分表；数值、分子分母、样本、状态、Wilson 区间规则见 `metrics.md` 第 8 节。发布版图片只使用玩家本机游戏资源或玩家自备的本地图片在运行时渲染，不打包游戏素材或第三方图片，也不提供打包遭遇图的构建选项。可配置分档阈值仍未实现。（2026-10-30 增加实际战损；2026-10-31 增加 T0–T4、中文 scoped CSV 与 4 行抬头。beta.2 的“导出本幕 PNG”按钮在同批改成“导出 PNG+CSV”，属于功能变更（同一次导出既写 PNG 又写 `metrics.csv`，幕选“全部”时每幕一张），在此登记，不属于 `AGENTS.md` 第 3 节禁止的文案润色）

### 复盘与回合重打

- 打开账本直接展示当前存档位的最近一局；局中优先展示正在玩的这一局。没有可读记录时显示历史列表的空状态，不跳到其他存档位。顶部固定“最近一局、历史对局、个人统计”，关闭按钮直接回到游戏。统计默认只显示职业、进阶、日期等常用筛选，其余收进“更多筛选”。（用户要求，2026-10-26）

- 参考《杀戮尖塔2》原生复盘：顶部按幕展示楼层路线，悬停楼层直接查看本层记录，点击固定详情并选择已保存的回合。整局总览展示遗物和最终牌组，牌组按同名、强化和永久数值合并数量。原始事件留在详细记录入口。（用户要求，2026-10-26）
- 已验证版本边界由同一处维护：基础依赖之外，可同装 SuperFastMode 1.0.8、求解器 0.9.6 及以后、Colored Map 2.4.1、Colored Powertips 2.3.0 和 Highlight Path 0.0.3。回合恢复白名单另加入 RunHistoryPlus 1.8.3、HideInfo 0.0.1、justclick 0.1.1 和 lolifontmod 0.2。这些组合已进入代码白名单，仍需手动回归录制、重打和快照提示。旧局没有保存的回合快照无法补录。（2026-10-29）

- 沿用 State Notes 0.4.0 的行为：单局按楼层复盘；开启回合快照后可在当前战斗回退到所选回合，或从历史附件启动隔离的练习实例。恢复失败回滚，回滚失败冻结。
- 在受支持的游戏与依赖版本下，附件兼容只看回合适配器、内嵌 SaveState 和快照格式，不看 Spire Ledger 自身版本，统计或界面更新不使已录附件失效。（用户决定，2026-10-25；M0 已实现）
- 练习不改写正式存档、战绩或解锁，也不进入正式统计；恢复失败时保留能回到正式游戏的存档。（proposed，现有实现已禁止练习存档，发布前原生探针验证）
- 练习窗口沿用玩家的语言、音量和窗口大小，并加载玩家当前启用的已审核 Mod（版本与白名单完全一致才带上；求解器不带进练习）。未审核的 Mod 不带。录制时装过、现在没装的已审核 Mod 不影响恢复，因为白名单只收不改战斗状态、不进快照字段的 Mod。（用户决定，2026-11-03，issue #25）
- 练习不止于一场战斗：从历史对局选一层“从此层继续”，或选一个回合“练习此回合”，打完这场战斗后回到地图，沿该局的地图继续往下打，直到玩家关闭练习窗口。为此每进入一层，账本保存一份游戏自身格式的楼层存档，做法与工坊 Mod Run Resumer 相同。没有楼层存档的旧局仍只能练当前这一场。楼层存档也可以作为 RL 项目的起点，是否使用由 RL 项目决定。（用户决定，2026-11-03，issue #24；尚未实现，路线见 [architecture.md](architecture.md)“练习环境与从此层继续”）

### 错误报告

- 沿用 State Notes：快捷键或设置页生成本地 JSON 错误报告，不上传。
- 报告只输出允许的结构化信息；账号、令牌和本地路径无论出现在字段、异常消息还是堆栈里都要去除。（proposed，现有实现只按字段名去除令牌，见 [architecture.md](architecture.md) M1）

## Non-goals

- 卡牌推荐、强弱评分或推荐理由。

- 产出训练数据或修改任何策略；记录（含楼层存档）能否进入训练由 RL 项目单独决定。
