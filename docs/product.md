## Purpose

Spire Ledger（尖塔账本）是《杀戮尖塔 1》的本地记录、统计与复盘 Mod，由用户维护和发布，GPL 开源。它把每局的事实如实记下来，汇总成玩家自己的统计和 Tierlist，并支持按层复盘和回合重打。它独立、离线，不依赖网络、求解器或训练环境，也能和用户的求解器 Mod 同装使用。

它要回答玩家的三类问题：我当时有哪些选择、选了什么；我在哪些遭遇、遗物和构筑下赢或输；我能否回到某个回合重打。因此三条事实必须可信：记录可追溯到当时的游戏状态，统计不重复计数且口径写明，练习和重打不损害正式存档与战绩。

它接替 State Notes（`sts1/sts1-state-notes`，0.4.0 未公开发布）：State Notes 的记录、复盘与重打能力迁入本项目并改名。TinyCat（MI，MPL-2.0）只作为统计口径与领域知识的参考，不并入代码，也不自动成为验收真值。

## Expectations

### 安装与运行

- 玩家放入一个 `SpireLedger.jar`，在 ModTheSpire 中勾选 BaseMod、StSLib 和 Spire Ledger 即可使用。
- 支持与求解器 Mod（`sts1solver`）同装：记录和统计照常工作，求解器执行的动作标为 `known_automation`，人的操作仍为 `human`；求解器加载时回合重打保持关闭。（用户决定，2026-10-25）
- 加载其他未审核的 Mod 时照常记录，操作来源记为 `unknown`，回合重打拒绝启用。
- 同时加载原装 SaveStateMod 时拒绝启动并提示移除。

### 记录

- 需要完整记录候选的决策类型以 [metrics.md](metrics.md) 的清单为准，至少包括战后选牌、商店和尼奥。每次选择确认前记录完整牌组（逐实例）、资源、遗物和全部候选；跳过、歌唱碗和最终离开分别记录，暂时关闭后重新打开不算一次新选择。商店候选记录展示时的价格和可买状态；尼奥记录全部选项的收益与代价。（商店与尼奥为新增，proposed）
- 资源快照包含累计获得金币，起点、计入的获得事件和 SL 后的路径口径写在 [metrics.md](metrics.md)。入层 HP 取进入房间、房间效果生效之前的值，不靠估算。（采样边界为 proposed）
- 构筑变化以前后锚点表示，不猜原因。SL 记为新分支并关联父检查点。
- 记录写在本机 `~/.spire-ledger/runs/<run_id>/`。异常退出后，已落盘的记录仍能从游戏内历史入口查看，不完整的尾部标为“中断”；派生文件损坏不得让整局记录消失。（proposed）
- 记录失败不阻断游戏；停录后持续显示停录状态，并在该局记录里标出缺失区间。（proposed）
- 记录格式升级只增字段、不改既有字段含义，旧记录持续可读；遇到不支持的版本时明确报告，并保留原文件不动。State Notes 0.4.0 的旧记录（`~/.sts1-state-notes/`，schema `sts1-state-v1`）原地只读，照常进入统计与复盘，新 Mod 不迁移、不改写。（用户决定，2026-10-25）

### 统计

**样本范围**

- 覆盖全部进阶，进阶作为筛选项；另可按职业、日期、结果、是否计入放弃、种子局、最小样本量筛选。（用户决定，2026-10-25）
- 每个逻辑对局只计一次：只使用最终有效路径及可确认的祖先片段，其余 SL 分支只用于复盘。练习实例、测试夹具和未完成局不进入正式统计。（proposed，沿用现有实现的分支口径）
- 统计按存档位分开：只统计当前存档位的局，不合并多个存档位，与游戏自带的历史记录一致。每日挑战、自定义模式和无尽模式不进入统计，也不提供单独查看。（用户决定，2026-10-25）
- 求解器参与的局照常进入统计，并标明自动化或人机混合来源。选择类排名排除已知自动化的选择；来源不明的选择计入，并单独显示其数量与占比（理由见 [metrics.md](metrics.md) 3.4）。（proposed）

**胜负口径**

- 每局保留三个独立事实：最终结局（胜、死亡、放弃、未完成）、是否通过第三幕、是否击杀心脏。（proposed，2026-10-25 协作者提出、审阅修订）
- “胜”默认指击杀心脏，可切换为“通过第三幕即算胜”。切换后，通过第三幕、死在第四幕的局也算胜；所选口径需要的事实缺失时，该局计为“未知”，不强判为败。（proposed）
- 结果筛选取值为全部、仅胜、仅败。放弃局默认排除；开启放弃开关后计为败，出现在“全部”和“仅败”中，“仅胜”始终不含放弃局。按胜负筛选时，所有胜率类指标（包括遗物的持有胜率）显示为“—”，其余指标照常计算。（proposed）

**来源合并**

- 数据来自本 Mod 的记录和原版 `.run`。旧 `.run` 里有 RunHistoryPlus 写入的字段时照读，但运行时不依赖 RunHistoryPlus。
- 相同 `play_id` 的多份来源合并为一个统计对象，同一记录的副本不重复计数，不按种子猜测关联。各字段保留来源，并按 [metrics.md](metrics.md) 声明的优先级取值；身份或同等级事实冲突时明确标记冲突，受影响的字段不参与计算。没有关联上的记录保留独立身份，并显示关联状态。结果与读取顺序无关。（proposed）

**指标与显示**

- 每个指标在 [metrics.md](metrics.md) 声明统计单位（局、战斗、选择次数）、适用样本、分子分母或模型含义、缺失与估算规则，以及最小样本量按什么计数。M1 开始补字段前，M2 和 M3 的指标清单先在这里定下。（proposed）
- 观测比率同时显示分子和分母；模型指标（如标准化抓率）显示有效样本量和模型口径。“已知为零”“未记录”“不适用”分开处理，缺失不当作 0；覆盖率按该指标的统计单位计算；估算值明确标注。
- 遗物统计：`.run` 里有 Relic Stats 写入的 `relic_stats` 时照读，按遗物汇总效果量（如燃烧之血回血、金神像金币）。只展示语义对照表已确认的效果维度和单位；只有上游按战斗计量的遗物才给每场战斗和每回合平均值，分母从获得该遗物时算起，无法确认分母时显示缺失。“持有”指该局结束时仍持有。效果量和持有胜率分别显示有效样本。运行时不依赖 Relic Stats，也不重写它的局内计数；对照表依据 Relic Stats（MIT）源码整理，NOTICE 署名。（proposed，2026-10-25 用户提出）
- 卡牌和尼奥的选择排名（Tierlist、标准化抓率）只描述玩家自己的选择行为，不给推荐理由，也不判断卡牌强弱；怪物排名描述所选样本里的遭遇结果。（proposed）
- 打开或关闭统计界面不改变局内状态，也不推进 RNG。

### 性能与存储

- 性能够用即可，不设硬性上限；不为性能引入难以维护的结构。M1 实测（1000 局打开约 6 秒，每次决策主线程停顿 p95 约 10 毫秒）作为回归基线，明显变差时再处理。（用户决定，2026-10-25）
- 回合附件和练习实例的磁盘占用可在游戏内查看，并可由玩家删除；磁盘空间不足时停止新增附件并提示，已有记录保留。（proposed）

### 导出

- CSV 表格与 Tierlist 图片。（用户决定，2026-10-25）
- 导出内容与当前界面的统计结果一致，并附带筛选条件、胜负口径、来源范围、有效样本量、缺失与估算标记，以及口径版本。CSV 写明编码和空值表示；图片至少保留影响解读的条件。（proposed）
- 图片只使用玩家本机游戏资源在运行时渲染，不打包游戏素材或第三方图片。

### 复盘与回合重打

- 沿用 State Notes 0.4.0 的行为：单局按楼层复盘；开启回合快照后可在当前战斗回退到所选回合，或从历史附件启动隔离的练习实例。恢复失败回滚，回滚失败冻结。
- 在受支持的游戏与依赖版本下，附件兼容只看回合适配器、内嵌 SaveState 和快照格式，不看 Spire Ledger 自身版本，统计或界面更新不使已录附件失效。（用户决定，2026-10-25；M0 已实现）
- 练习不改写正式存档、战绩或解锁，也不进入正式统计；恢复失败时保留能回到正式游戏的存档。（proposed，现有实现已禁止练习存档，发布前原生探针验证）

### 错误报告

- 沿用 State Notes：快捷键或设置页生成本地 JSON 错误报告，不上传。
- 报告只输出允许的结构化信息；账号、令牌和本地路径无论出现在字段、异常消息还是堆栈里都要去除。（proposed，现有实现只按字段名去除令牌，见 [architecture.md](architecture.md) M1）

### 发布与许可

- 由用户发布；仓库 GitHub 私有（2026-10-25），公开时间由用户决定。
- 先只在 GitHub 上内测，暂不发布到 Steam Workshop；每次发布仍由用户逐次授权。（用户决定，2026-10-25）
- 自有代码 GPL-3.0。内嵌的改造 SaveState 仍在主 jar 内，它的上游没有许可证，不在 GPL 授权范围内；NOTICE 写明署名、来源和修改摘要，上游 issue #13 回复后更新。（用户决定，2026-10-25）

## Non-goals

- 卡牌推荐、强弱评分或推荐理由。
- 上传、遥测或云同步。
- 产出训练数据或修改任何策略；记录能否进入训练由 RL 项目单独决定。
- xlsx 导出。
- 支持自定义角色、卡牌或怪物的保证。
